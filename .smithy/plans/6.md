## Approach
1. **Bring the docs in.**
   - Copy both specs to `docs/specs/` unchanged. CLAUDE.md on `main` already links the multi-app spec, but that file doesn't exist on `main` yet.
   - Don't copy the bug report to the repo root. It is an upstream Dapr issue, and the only thing it requires of this repo is the required-`appID` guard (step 4). Instead, link dapr/dapr#10217 and fix PR #10218 from the "hardening guard" paragraph of the multi-app spec.
2. **Dependencies.** Bump to the versions the workflow client needs:
   - `durabletask-go` v0.12.1 (for `ListInstanceIDs`, `GetInstanceHistory` and `RerunWorkflowFromEvent`);
   - `dapr/go-sdk` v1.15.0, `modelcontextprotocol/go-sdk` v1.6.0, grpc 1.80, otel 1.43.

   Then run `go mod tidy`. Because go-sdk v1.6.0 deprecates `HasTools`, use `Capabilities` from the start rather than adding `HasTools` and fixing it later:
   ```go
   Capabilities: &mcp.ServerCapabilities{
       Logging: &mcp.LoggingCapabilities{},
       Tools:   &mcp.ToolCapabilities{ListChanged: true},
   },
   ```
   Completions are still added automatically because `CompletionHandler` is set.
3. **New `pkg/workflow`, written from scratch** using the usual tool-package pattern (narrow `WorkflowClient` interface, `jsonschema` arg descriptions, OTEL spans, `IsError` results).
   - Tools: `start_workflow`, `get_workflow_status`, `get_workflow_history`, `rerun_workflow`, `list_workflows`, `pause_workflow`, `resume_workflow`, `terminate_workflow`, `raise_workflow_event`, `purge_workflow`.
   - These base tools have no spec of their own. Their scope comes from CLAUDE.md plus the tool list on the branch.
4. **Multi-app support, following the spec:**
   - `config.go`: `ParseAppsConfig(string) (map[string]string, error)`. Entries are trimmed. Malformed entries and duplicate app-ids are errors.
   - A registry holding the default client and a `map[appID]WorkflowClient`, populated by `RegisterTools(server, defaultClient, defaultAppID, byAppID)`. A `clientFor(appID)` helper returns an error listing the configured app-ids when the `appID` is unknown.
   - The required-`appID` guard from the bug report: when apps are configured, every per-instance tool must get an `appID`. The sidecar's own app-id is accepted.
   - `list_workflows` fan-out when no `appID` is given:
     - results are merged, with `app_id` on each instance plus `counts_by_app`;
     - a failure in one app becomes a warning for that app instead of failing the call;
     - `limit` applies per app, and continuation tokens are returned per app (`continuation_tokens`).
   - Mutating tools never fan out.
5. **`main.go`**
   - Read `DAPR_MCP_SERVER_WORKFLOW_APPS` and build one client per app with `NewClientWithAddress` plus `dtworkflow.NewClient(conn.GrpcClientConn())`.
   - Connect to each app with the **same retry policy as the primary client (5 attempts, 2s apart)**, then exit fatally if it still fails.
   - Resolve the default app-id with `GetMetadata().ID`, falling back to `"default"`.
   - Always register the workflow tools.
   - Update the server instructions so agents know to pass `appID` in multi-app mode.
6. **Transport.** Replace `NewSSEHandler` with `NewStreamableHTTPHandler`, stateful by default, and add a `--stateless` flag / `DAPR_MCP_SERVER_STATELESS=true` option. The notifications spec depends on the stateful mode. Update the README for the new environment variables, and update CLAUDE.md where it still says SSE.
7. **Out of scope:** the workflow-notifications spec. It is a Draft and still has open decisions: pub/sub vs. polling as the event source, the event contract, and whether clients support elicitation. Only its prerequisite, stateful Streamable HTTP, is built here.
8. **Check against `7554c56`.** Diff the new code against the branch tool by tool, and record the result in the PR description. Known differences:
   - **Pool connections:** the branch connects to pool apps with no retry; this plan uses the retry the spec requires.
   - **Branch changes with no spec:** `fix(metadata)` and `fix(crypto)` put component details and cipher/plain text into the text content. Port them with tests, since they are small, self-contained bug fixes.
   - **`pkg/auth/sentry.go` and `pkg/conversation` diffs:** these come from the dependency bump. Re-derive them only if the build requires it.
9. Run gofmt/goimports, build, test and lint.
10. Push the branch and open a new PR to `main`. Once it merges, close #3 **unmerged** with a link to the new PR, since its commits are not reused.
11. Don't commit the `dapr-mcp-server` binary or `.smithy/tmp/`.
