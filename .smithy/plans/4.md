# Plan — Issue #4: Update the libraries (latest Dapr) + slim down the build image

## Context
Dependencies are pinned to Dapr `go-sdk v1.13.0` / `dapr v1.16.0` (Go 1.25). Latest stable releases (checked via `go list -m -versions`): **`github.com/dapr/go-sdk v1.15.0`** and **`github.com/dapr/dapr v1.18.4`** (`durabletask-go v0.12.5`, `kit v0.18.3` transitively). All Alpha/Beta SDK methods we use (`ConverseAlpha1/2`, `TryLockAlpha1`, `UnlockAlpha1`, `QueryStateAlpha1`, `*JobAlpha1`) still exist in go-sdk v1.15.0. Note: `dapr v1.18.4` declares `go 1.26.6`, so the module's `go` directive and the Docker builder must move to Go 1.26.

The Dockerfile is already multi-stage → distroless, but has waste: `git` installed in the builder, no `.dockerignore` (context ships `.git`, `test/`, the root `dapr-mcp-server` artifact), no `-trimpath`, QEMU-emulated builds for arm64, and a `HEALTHCHECK` calling a `--health-check` flag that **does not exist** in `main.go` (exec-form with `|| exit 1` in a shell-less image — always unhealthy).

## Changes

### 1. Library update (`go.mod`, `go.sum`)
- `go get github.com/dapr/go-sdk@v1.15.0 github.com/dapr/dapr@v1.18.4`, then `go get -u ./...` for the other direct deps (MCP go-sdk, OTEL, grpc, protobuf, go-oidc, go-jose, go-spiffe, testify) and `go mod tidy`.
- `go` directive becomes `1.26.6` (forced by dapr). CI/release use `go-version-file: go.mod`, so no workflow change needed.
- Fix any compile breaks from API drift in `pkg/*/tools.go` and `test/mocks/dapr_client_mock.go` (it imports `github.com/dapr/dapr/pkg/proto/runtime/v1`); keep the package-local client interfaces in sync with the SDK signatures.
- README "Prerequisites": `Go 1.21+` → `Go 1.26+`; mention Dapr runtime 1.18 as the tested version.

### 2. Slimmer, faster image (`Dockerfile`, new `.dockerignore`)
- Builder: `FROM --platform=$BUILDPLATFORM golang:1.26-alpine AS builder`; drop `apk add git` (modules come from the proxy; CA certs not needed with distroless runtime). Cross-compile natively with `ARG TARGETOS TARGETARCH` → `GOOS=$TARGETOS GOARCH=$TARGETARCH` (removes QEMU emulation for arm64 in `release.yml`).
- BuildKit cache mounts for `/go/pkg/mod` and `/root/.cache/go-build`.
- Build flags: add `-trimpath`, keep `-ldflags="-s -w -X main.Version=${VERSION}"`.
- Runtime: `gcr.io/distroless/static-debian13:nonroot` (current distroless base, already ships CA certs + nonroot user).
- Remove the broken `HEALTHCHECK` (no such flag; K8s/Dapr use the HTTP `/healthz`-style endpoints from `pkg/health` instead). Keep `EXPOSE`, `ENTRYPOINT`, `CMD`.
- Add `.dockerignore`: `.git`, `.github`, `.smithy`, `test/`, `docs/`, `*.md`, `dapr-mcp-server` (root artifact), coverage files.

## Critical files
`go.mod`, `go.sum`, `Dockerfile`, `.dockerignore` (new), `README.md`, possibly `pkg/*/tools.go` + `test/mocks/dapr_client_mock.go` if SDK signatures changed.

## Testing
- No new behavior → no new tests; existing suite is the regression check: `go test -race ./pkg/...` (keep ≥80% coverage), `go vet ./...`, `golangci-lint run`, and `go test -tags integration ./test/integration/`.
- Update existing unit tests/mocks only where the SDK upgrade changes types.
- Image: `docker build -t dapr-mcp-server:test .` and `docker buildx build --platform linux/amd64,linux/arm64 .`; compare `docker images` size before/after; `docker run --rm -p 8080:8080 dapr-mcp-server:test` and hit the health endpoint.
- Manual smoke (if a Dapr 1.18 runtime is available): `dapr run --resources-path components -- ./dapr-mcp-server --http localhost:8080`, call `get_components` and a state tool.
